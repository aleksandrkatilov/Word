# Этап 0 — выбор движка и прототип

ТЗ: «Word Editor Technical Specification», v1.0 от 07.11.2026. Состояние на 07.11.2026.

## 1. Решение

**Движок:** Syncfusion SfRichTextBoxAdv (WPF DOCX Editor) + SfRichTextRibbon + DocIO, версия 35.1.43. **Оболочка:** .NET 8, WPF.

Почему:

- готовая постраничная разметка (`LayoutType.Pages`), колонтитулы, поля PAGE/NUMPAGES, таблицы, списки, стили, поиск и замена, отмена и повтор, печать — это закрывает основную часть P0 без собственного движка разметки;
- лента в стиле Word идёт готовым компонентом и привязывается к редактору одной строкой;
- импорт и экспорт DOCX, TXT; PDF через DocIO;
- лицензия: бесплатная Community License для компании с выручкой меньше $1 млн в год, не больше 5 разработчиков и 10 сотрудников. При выходе за порог — коммерческая лицензия (Team на 5 разработчиков — от $395 в месяц);
- тот же стек (.NET/WPF), что рекомендует ТЗ; Electron и WebView не используются.

Главные риски выбора (проверяются на первой сборке, см. раздел 4): движок импортирует документ в свою модель и при сохранении пишет пакет заново, поэтому неподдерживаемые конструкции теряются. Это закрыто проверкой пакета до открытия и режимом «только чтение» (DOCX-01); отделимые части OOXML возвращаются в пакет оболочкой.

## 4. Результаты проверки

Проверено в Linux-окружении (сборка WPF здесь невозможна, поэтому ядро и утилиты проверены отдельно):

- ядро и утилита собираются без предупреждений; **25 из 25 тестов** проходят;
- исходники WPF проходят синтаксическую проверку компилятором C#; XAML корректен; полная сборка — на Windows (CI или `build.ps1`);
- перенос отделимых частей проверен на реальном файле: после удаления customXml и пользовательских свойств и возврата ядром различий нет; файл открывают python-docx и LibreOffice.

Проверка пакета на стартовом эталонном наборе:

| Файл | Результат |
|---|---|
| 01 — стили, списки, 5 страниц, колонтитулы, PAGE/NUMPAGES | Открывается для правки |
| 02 — таблицы, объединения, заливка, длинная таблица с повтором заголовка | Открывается для правки |
| 03 — изображения в строке, гиперссылка, альбомная страница, разрыв | Открывается для правки |
| 04 — формула, исправление, элемент содержимого, customXml, пользовательские свойства | Только чтение с отчётом (формула и элемент содержимого) |
| 90 — пароль или DOC | Отклонён: «защищён паролем или старый формат DOC» |
| 91 — обрезанный ZIP | Отклонён: повреждён |
| 92 — путь `../evil.txt` в ZIP | Отклонён: недопустимый путь |
| 93 — ZIP без DOCX | Отклонён: не документ DOCX |

Для проверки инструмента сравнения эталоны 01–03 прогнаны через круговой обмен в LibreOffice. `pero-probe compare` нашёл одну реальную потерю — стиль `Hyperlink` в файле 03, а пересоздание служебных частей отметил как информационное. Тот же прогон нужно повторить для Syncfusion (раздел 5).

## 5. Первая сборка на Windows — чек-лист

1. `build.ps1` → собирается без ошибок; запуск `artifacts\Pero\Pero.exe`. Лента на русском.
2. Открыть `samples\docx\01…03` (генерирует `build.ps1`). Проверить: страницы, колонтитулы, номера страниц, списки, объединённые ячейки, повтор заголовка таблицы, изображения.
3. В каждом: изменить текст, стиль, ячейку, размер изображения → Ctrl+S → открыть в Word: Word не предлагает восстановление (QA-01). Затем «Этап 0 → Проверка круговым обменом» и `pero-probe compare` исходника с сохранённым файлом. Потери внести в `compat-registry.json` с `Verified: true`.
4. Открыть `04-unsupported.docx` → предложение «только чтение» с отчётом; «Сохранить копию» не даёт перезаписать исходник.
5. Файлы 90–93 → понятные сообщения, без падения.
6. Набрать текст → подождать 30 с → завершить процесс через диспетчер задач → запустить → предложение восстановления (QA-04).
7. Открыть файл, изменить его в Word и сохранить, затем Ctrl+S в «Пере» → предупреждение о внешнем изменении.
8. Файл с атрибутом «только чтение» → полоса сообщения и сохранение копии.
9. Экспорт PDF → сравнить с предпросмотром печати (PAGE-03).
10. Взять журнал `%LOCALAPPDATA%\Pero\Logs` — строки `PERF` по открытию и сохранению — и сравнить с порогами раздела 6 ТЗ на документе в 100 страниц.

Места, где API движка не удалось проверить без сборки (если что-то не так — правка на несколько строк):

- команды «Открыть / Сохранить» из бэкстейджа ленты должны идти через перехват `PreviewExecuted`; если бэкстейдж грузит файлы напрямую, его заменяем своим меню «Файл»;
- добавление вкладки «Этап 0» в ленту (при сбое те же команды доступны в строке состояния);
- `ZoomFactor` — тип и диапазон (ползунок 25–500);
- `CurrentPageNumber` возвращает первую видимую страницу, а не страницу курсора — для UI-06 уточнить.

## 6. Известные ограничения и что делать на этапе 1

- **SCOPE-01.** В готовой ленте есть команды вне P0: шифрование, ограничение редактирования, сохранение в HTML, XAML, DOC. Сейчас сохранение в этих форматах перехвачено и выдаёт сообщение. На этапе 1 эти кнопки нужно убрать из ленты.
- **PAGE-03.** PDF вёрстает DocIO, а экран — SfRichTextBoxAdv. Если отклонение больше 1 мм (QA-02), печатать в PDF через драйвер «Microsoft Print to PDF» из самого редактора.
- **ARCH-02.** Загрузка и запись движком идут в потоке интерфейса; проверка пакета, перенос частей и запись на диск — в фоне. На 100 страницах замерить; при превышении порогов — индикатор и `LoadAsync`.
- **LINK-01.** Проверку схемы ссылки при Ctrl+щелчке нужно добавить перехватом навигации.
- Своя кнопка «Файл» с последними файлами, свойствами и настройками (UI-02) — сейчас последние файлы есть в меню строки состояния.
- Утверждение 12 эталонных экранов, проверки доступности (экранный диктор, высокая контрастность), DPI 100–200%.
- Набор эталонов довести до 40 файлов раздела 7: нужны реальные документы из Word.
